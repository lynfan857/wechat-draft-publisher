# WeChat Draft Publisher PRD

## 1. 项目定位

WeChat Draft Publisher 是一个 Obsidian 桌面端插件，帮助中文内容创作者把当前 Markdown 笔记整理成微信公众号文章，并发布到微信公众号草稿箱。

插件的核心价值不是替代微信公众号后台，而是把“从 Obsidian 写作到公众号草稿”的重复操作缩短为一个稳定流程：

1. 读取当前笔记。
2. 预览公众号排版。
3. 检查标题、摘要、封面、图片、微信连接。
4. 上传正文图片和封面。
5. 创建或更新公众号草稿。
6. 把草稿状态写回笔记。

## 2. 目标用户

第一版只服务一个明确用户画像：

- 使用 Obsidian 写作和管理内容。
- 文章最终发布到微信公众号。
- 有自己的微信公众号 AppID/AppSecret。
- 能接受在本机配置微信 API 和 IP 白名单。
- 需要稳定地把 Markdown 转成公众号草稿，而不是追求复杂营销自动化。

暂不服务：

- 团队多人协作发布。
- 多公众号矩阵管理。
- 完整内容 CMS。
- 自动群发。
- 非微信公众号平台。

## 3. 核心场景

### 场景 A：第一次配置插件

用户安装插件后，需要知道自己该填什么、去哪里找、为什么连接失败。

成功标准：

- 用户能在设置页填 AppID/AppSecret。
- 用户知道当前公网 IP 要加入微信公众号后台白名单。
- 用户可以通过“测试连接”确认配置有效。
- AppSecret 不会因为误操作被空值覆盖。

### 场景 B：发布一篇新文章到草稿箱

用户打开一篇 Markdown 笔记，进入公众号发布工作台。

成功标准：

- 插件自动提取标题、作者、摘要、正文图片。
- 用户可以预览公众号排版效果。
- 用户可以选择主题。
- 用户可以选择封面来源。
- 发布前检查能明确指出阻塞问题。
- 点击发布后，文章出现在公众号草稿箱。
- 插件写回草稿 ID 和同步状态。

### 场景 C：更新已发布过的草稿

用户修改 Obsidian 笔记后，希望更新同一篇公众号草稿。

成功标准：

- 插件能识别当前笔记已关联草稿。
- 插件能提示“草稿已是最新”或“有更新待同步”。
- 用户可以更新原草稿，也可以另存为新草稿。
- 更新后 frontmatter 中的同步状态刷新。

### 场景 D：复制 HTML 手动粘贴

用户不想直接调用微信 API，或者当前 API 配置不可用，只想复制公众号 HTML。

成功标准：

- 用户可以复制清理后的 HTML。
- 插件提示复制 HTML 与直接发布在图片处理上的差异。
- 不把复制路径和发布路径混淆。

## 4. 第一版功能边界

必须做好：

- 当前笔记预览。
- 主题切换。
- 标题、作者、摘要、原文链接编辑。
- 封面来源选择。
- 正文图片上传。
- 封面上传或使用已有 media_id。
- 新建草稿。
- 更新草稿。
- 发布检查。
- 微信连接测试。
- 基础错误提示。
- 发布状态写回 frontmatter。

明确不做：

- 自动群发。
- 图文多篇合并发布。
- 多账号管理。
- 云端中转服务。
- AI 自动改写文章。
- AI 生成封面。
- 复杂主题市场。
- Obsidian 移动端支持。

## 5. 关键约束

### 微信 API 约束

- 获取 access_token 需要 AppID/AppSecret。
- 本机直连微信 API 时，当前公网 IP 必须在微信公众号后台白名单。
- 正文图片和封面素材走不同接口。
- 草稿接口权限以微信公众号后台实际账号能力为准。

### Obsidian 插件约束

- 第一版只支持桌面端。
- AppSecret 存在 Obsidian SecretStorage，不写入 data.json。
- 插件不能假设所有用户都有相同的 vault 结构。
- 图片路径必须兼容 Markdown 图片和 Obsidian wikilink 图片。

### 内容一致性约束

- Obsidian 预览、复制 HTML、发布草稿应尽量一致。
- 但微信编辑器会清理部分 HTML/CSS，插件只能做兼容性降低风险，不能保证像素级一致。

## 6. 成功指标

第一阶段成功：

- 用户自己能稳定发布 3 篇不同结构的文章。
- 至少 1 个外部测试用户能完成安装、配置、发布。
- 常见失败原因能在界面里被解释清楚。

第二阶段成功：

- 5 个外部测试用户中，至少 4 个能不看额外指导完成首篇草稿发布。
- 发布失败时，用户能根据错误提示知道下一步该做什么。

## 7. 风险

- AppSecret 和微信权限属于敏感配置，需要持续强调安全边界。
- IP 白名单会因为用户网络变化导致连接失败。
- 微信编辑器 HTML 兼容性不可完全控制。
- 外部用户的图片路径、附件命名和 vault 结构差异会暴露更多边界问题。
