# Interaction Design

## 1. 设计原则

插件界面应像一个发布工作台，而不是营销页面。

原则：

- 信息优先：用户一眼知道当前文章能不能发布。
- 操作就近：哪里出问题，就在那里给修复入口。
- 状态明确：区分未发布、已同步、有更新、发布中、发布失败。
- 少解释概念：尽量不要求用户理解微信 API 内部概念。
- 保持 Obsidian 原生感：使用 Obsidian 默认按钮、输入框、颜色变量和密度。

视觉方向：

- 克制、工具型、中等信息密度。
- 卡片只用于独立检查项、结果提示和图片选择，不做装饰性卡片堆叠。
- 主色跟随当前主题色，避免单独做强品牌视觉。

## 2. 工作台信息架构

目标结构：

```text
公众号发布
当前笔记路径 / 草稿状态 / 最近同步时间

工具栏
[刷新预览] [发布/更新草稿] [另存为新草稿] [复制 HTML] [主题选择]

发布信息
标题 / 作者 / 摘要 / 原文链接

封面
封面来源选择 / 图片缩略图 / media_id 输入

发布检查
标题 / 摘要 / 封面 / 正文图片 / HTML 兼容性 / 微信连接

预览
公众号正文预览
```

当前实现可以逐步演进，不要求一次性重写布局。

## 3. 顶部状态栏

顶部应回答三个问题：

1. 当前连接的是哪篇笔记？
2. 这篇笔记是否已经关联公众号草稿？
3. 当前内容是否需要同步？

状态文案：

- 未选择笔记：`打开一篇 Markdown 笔记后即可预览`
- 未关联草稿：`预览已生成`
- 已关联且未变化：`草稿已是最新`
- 已关联且有变化：`草稿有更新待同步`
- 发布中：`正在上传正文图片 1/4...`
- 发布失败：显示失败摘要，并在结果区显示详细原因。

## 4. 工具栏按钮

按钮分主次：

- 主按钮：发布或更新草稿。
- 次按钮：另存为新草稿、复制 HTML、刷新预览。
- 选择控件：主题选择。

按钮状态：

| 状态 | 主按钮 |
| --- | --- |
| 未关联草稿 | 发布到草稿箱 |
| 已关联且内容未变 | 草稿已是最新 |
| 已关联且内容有变化 | 更新草稿 |
| 发布中 | 禁用，显示当前操作 |
| 阻塞错误 | 禁用或点击后定位到错误 |

`另存为新草稿` 应始终作为次按钮，不要和主按钮争夺注意力。

## 5. 发布信息区

字段：

- 标题
- 作者
- 摘要
- 原文链接

字段来源：

| 字段 | 默认来源 |
| --- | --- |
| 标题 | frontmatter title，或一级标题，或文件名 |
| 作者 | frontmatter author，或插件默认作者 |
| 摘要 | frontmatter digest，或正文首段 |
| 原文链接 | frontmatter content_source_url |

保存行为：

- 编辑字段先只影响当前工作台预览。
- 点击“保存到笔记属性”后写入 frontmatter。
- 发布时使用当前工作台里的值。

## 6. 封面设置区

封面区不要让用户先面对 `cover` 字段。

封面来源：

```text
○ 使用正文第一张图
○ 使用指定图片
○ 使用已有微信素材 media_id
```

### 使用正文第一张图

默认选项。

行为：

- 如果正文有图片，使用第一张正文图片作为封面。
- 发布时上传为微信永久素材。
- 不写入 `cover` frontmatter。

适用：

- 大多数普通文章。
- 用户不想单独管理封面。

### 使用指定图片

行为：

- 展示当前笔记检测到的所有图片。
- 每张图显示缩略图、文件名、大小、类型。
- 用户点击某张图后设为封面。
- 保存时写入：

```yaml
cover: path/to/image.png
```

适用：

- 封面不是正文第一张图。
- 发布素材文件夹里有专门封面图。

### 使用已有微信素材 media_id

行为：

- 显示 `media_id` 输入框。
- 发布时不上传封面，直接使用该素材 ID。
- 保存时写入：

```yaml
cover_media_id: xxx
```

适用：

- 用户已经在微信公众号后台上传过封面。
- 多篇文章复用同一个默认封面。

### 默认封面素材 ID

设置页里的默认封面素材 ID 只作为 fallback。

优先级：

1. 当前笔记 `cover_media_id`
2. 当前笔记指定封面图片
3. 正文第一张图
4. 设置页默认封面素材 ID

## 7. 发布检查区

检查项分三级：

- `error`：必须处理，否则不能发布。
- `warn`：可以发布，但建议处理。
- `ok`：正常。

检查项：

| 检查项 | error | warn | ok |
| --- | --- | --- | --- |
| 标题 | 空标题 | 过长可提醒 | 有标题 |
| 摘要 | 不阻塞 | 空摘要或超过 120 字 | 长度合适 |
| 封面 | 没有图片也没有 media_id | 使用默认素材 ID 可提醒 | 有明确封面 |
| 正文图片 | 图片找不到、格式不支持、超过 10MB | 正文无图 | 图片可上传 |
| HTML 兼容性 | 发布 HTML 中仍有本地图片 | 样式可能被微信忽略 | 无明显问题 |
| 微信连接 | AppID/AppSecret/IP 不可用 | token 即将过期可提醒 | 连接正常 |

下一步优化目标：检查项应可操作。

例：

```text
封面缺失
请选择正文图片作为封面，或填写微信素材 media_id。
[选择正文图片] [填写 media_id]
```

```text
微信连接失败
当前公网 IP 可能不在公众号后台白名单。
[复制当前 IP] [打开微信后台]
```

## 8. 发布结果区

发布成功：

```text
公众号草稿已更新。
草稿 ID：xxx。正文图片 4 张，封面已就绪。HTML 38.2 KB。
```

发布失败：

```text
公众号草稿发布失败。
获取 access_token 失败：当前公网 IP 不在白名单。
```

要求：

- 结果区保留在工作台中，不只依赖 Notice。
- 失败信息要尽量转成用户能理解的话。
- 对可修复错误给下一步入口。

## 9. 设置页结构

目标分组：

```text
微信公众号
- AppID
- AppSecret
- 当前公网 IP
- 测试连接
- 打开微信后台基本配置

默认发布信息
- 默认作者
- 默认主题
- 默认封面素材 ID

高级
- 清除上传缓存
- 导出诊断信息
- 重置插件状态
```

AppSecret 行为：

- 输入新值后，必须点击“保存 AppSecret”才覆盖。
- 已保存时显示“已保存，输入新值可覆盖”。
- 不把 AppSecret 写入 data.json。

## 10. 预览区

预览区目标：

- 显示公众号正文的近似最终效果。
- 主题切换即时生效。
- 不承担发布检查职责。

后续可优化：

- 手机宽度预览模式。
- 桌面宽度阅读模式。
- 显示最终 HTML 字节大小。
- 高亮未成功上传的图片占位。

## 11. 不做的交互

暂不做：

- 多账号切换器。
- 图文多篇列表编辑。
- AI 一键生成标题。
- AI 生成封面。
- 微信后台草稿列表同步。
- 发布后自动打开浏览器检查草稿。

这些能力会显著扩大范围，应等基础工作台稳定后再评估。
